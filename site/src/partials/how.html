02How it works

Three roles, all ordinary Claude Code sessions in tmux windows on a private server (tmux -L jiva-<repo>), so they never touch your own tmux.

desk
The only session you talk to. Relays asks and reports, and brings real decisions to you: server and deploy changes, spend, destructive ops, sudo.
boss
Splits a goal into task cards and assigns them. Doesn't write product code.
workers
One card each. They claim paths, do the work, run checks, ship.
watchdog
Not an LLM. A bash loop that writes .jiva/state.json, the tmux status bar, flags and respawns.

Asks bubble up. A worker that is stuck asks the boss. If the boss can't decide, it files a typed ask (question, options, default, class) for the desk. The watchdog batches open asks into one digest for the desk, which puts them to you. You answer in one place with jiva answer <id>. Only a decision ever falls back to its default; permission, deploy, spend and the other protected classes wait for you.
