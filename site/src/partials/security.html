07Security, plainly

JIVA adds no server and no account. It's bash, tmux and the Claude Code CLI you already run, on your machine.

  • Local only. Every session runs in tmux on your machine, on a private socket per repo (tmux -L jiva-<repo>).
  • Permissions stay yours. Sessions run in Claude Code's auto mode with your own allowlist. Anything outside it prompts natively in that session's pane, and only a human answers. JIVA ships no hook that auto-approves anything (an opt-in relay can forward a prompt to the desk, never decide it), and never clicks through the workspace-trust dialog. jiva pending lists the panes waiting on you.
  • No inbound ports. The dashboard binds 127.0.0.1 only, answers GET and nothing else, serves a web root of symlinks, and rejects .. paths.
  • State is numbers and enums. state.json holds token counts, percentages, status words and session names. No prompts, no output, no file contents.
  • Secrets are never printed. Keys are read inside scripts only. Sessions are told not to cat them, and just sec scans the full git history for leaks.
  • This page: static files, a strict Content-Security-Policy, self-hosted fonts, no cookies, no analytics, no third-party requests.
