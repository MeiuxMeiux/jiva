08Built with itself

The watchdog, the verbs, the dashboard and this page were written by JIVA sessions, each working from a task card and ending in a handoff. The fleet that runs the work is the fleet that wrote the runner.

Open source, public alpha: github.com/MeiuxMeiux/jiva.

Install (public alpha)

Linux or WSL2. bash ≥4, git, tmux ≥3.2, jq ≥1.6, just, python3, util-linux (flock, setsid), coreutils, Claude Code. Optional: gh, shellcheck, gitleaks. macOS: untested (needs Homebrew bash, coreutils, util-linux).

One line: checks the dependencies, clones JIVA into ~/.jiva and prints the PATH line to add.

$ npx jiva-fleet init

Or clone the repo and put its bin/ on your PATH:

$ git clone https://github.com/MeiuxMeiux/jiva ~/jiva
$ export PATH="$HOME/jiva/bin:$PATH"

Then, inside any repo:

$ jiva init     # .jiva/, gitignore, CLAUDE.md pointer
$ jiva up 3     # watchdog + boss + 3 workers
$ jiva doctor   # budgets as tests
$ jiva down     # kill the private tmux server

Workers: soft cap 6 (above it, JIVA_CONFIRM=1), hard cap 12. Each one burns quota like a session of its own. Hooks reach each pane through a --settings file, or through the optional plugin (jiva plugin install); jiva up prints which one it used.

First run in a new repo: jiva up stops at Claude Code's workspace-trust dialog, once per repo. Attach with tmux -L jiva-<repo> a and accept it yourself. JIVA never auto-accepts it.

Permissions: sessions run in hidden panes, so a permission prompt stalls one until you answer it (jiva pending shows where). Allow the routine commands first (Claude Code's auto mode is recommended); docs/QUICKSTART.md in the repo has a sample allowlist.

JIVA Micro: no install

One markdown file for any repo. Paste it in as JIVA.md and Claude Code walks it in order: check the host and quota, cut startup tokens, add the shared-checkout rules, then launch a small fleet in plain tmux. Pitfalls included.

View micro.md

Or from a terminal: npx jiva-fleet micro writes it as JIVA.md.
